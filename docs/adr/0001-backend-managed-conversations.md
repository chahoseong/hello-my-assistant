# Conversation 이력은 백엔드에서 관리한다

## 배경

멀티턴 대화를 이어가기 위해 이전 `Agent` 메시지 이력을 누가 관리할지 결정해야 한다.

## 결정

이어지는 대화의 이력은 백엔드의 `Assistant`가 관리한다. 클라이언트는 전체 이력 대신 서버가 발급한 `Conversation` 식별자만 전달한다.

사용자의 첫 메시지가 새 `Conversation`을 생성하고 첫 `Turn`을 시작한다.

## 이유

- 프레임워크에 종속적인 `Tool` 및 메시지 이력을 `Assistant` 내부에 감출 수 있다.
- 클라이언트가 제공한 이력을 신뢰하지 않아도 된다.
- 별도의 `Conversation` 생성 요청으로 인한 왕복을 피할 수 있다.

## 고려한 대안

클라이언트가 전체 이력을 관리하는 방식과 `Conversation` 생성 후 첫 메시지를 별도로 전송하는 방식을 고려했지만 채택하지 않았다.

## 이 결정에 포함하지 않는 사항

인메모리 저장소, 영속성, 긴 `Conversation`의 컨텍스트 관리는 별도로 결정한다.
